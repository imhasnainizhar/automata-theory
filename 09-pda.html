Chapter 9 · Context-Free Languages

Pushdown Automata

Give a finite automaton a stack — unbounded memory, but accessible only at the top — and it can match nested structure. Pushdown automata are to context-free grammars what finite automata are to regular expressions: the machine side of the same coin.

⏱ 70 minPrerequisite: Chapters 4, 8Nondeterministic simulator

The intuition

Intuition — a stack of plates

To check $0^n1^n$, push a plate for every 0; pop a plate for every 1. If you run out of plates too early, or have plates left at the end, reject. The stack is unbounded, so it can count arbitrarily high — but you can only see the top plate, so you cannot, for example, compare two separate counts.

A stack is exactly the memory needed for nesting: the most recently opened bracket is the first one that must be closed. That is why the stack is the natural memory for recursion — and why your CPU uses a call stack.

Definition

Definition — pushdown automaton (PDA)

A PDA is a 6-tuple $P = (Q, \Sigma, \Gamma, \delta, q_0, F)$ where $Q$, $\Sigma$, $q_0$, $F$ are as for an NFA, $\Gamma$ is the finite stack alphabet, and

$$\delta : Q \times \Sigma_\varepsilon \times \Gamma_\varepsilon \to \mathcal{P}(Q \times \Gamma^*).$$

A transition $(r, \gamma) \in \delta(q, a, X)$, drawn as an arrow $q \to r$ labelled $a, X \to \gamma$, means: in state $q$, reading $a$ (or nothing, if $a = \varepsilon$), with $X$ on top of the stack (or ignoring the stack if $X = \varepsilon$), pop $X$, push $\gamma$, and go to $r$.

$P$ accepts $w$ if some sequence of moves reads all of $w$ and ends in a state of $F$.

The PDA is nondeterministic by default — and unlike for finite automata, this matters: deterministic PDAs are strictly weaker (see below).

We often push a special bottom marker $\bot$ first, so that the machine can detect an empty stack. A configuration (instantaneous description) is a triple $(q, \text{remaining input}, \text{stack contents})$, and $\vdash$ denotes one move.

Example 2 — even palindromes: nondeterminism at work

$L = \{ww^R : w \in \{0,1\}^*\}$. The machine pushes the first half, then pops while matching the second half. But where is the middle? It cannot know — so it guesses, with an ε-move from the “push” phase to the “pop” phase. Only the branch that guesses correctly survives to accept.

Acceptance by final state vs. empty stack

Some books define acceptance differently: $P$ accepts by empty stack if some run reads all of the input and empties the stack (in any state). The two notions are equivalent for nondeterministic PDAs:

  • Final state → empty stack: from every accept state, add ε-moves to a new “drain” state that pops everything. (Push a fresh bottom marker first so the original machine never empties its stack by accident.)
  • Empty stack → final state: push a fresh bottom marker $\bot'$ first; whenever $\bot'$ is exposed, the original stack is empty — move to a new accept state.

The equivalence theorem

Theorem — PDAs and CFGs are equivalent

A language is context-free if and only if some pushdown automaton recognizes it.

CFG → PDA: simulate leftmost derivations

Intuition — the stack holds “what I still expect to see”

Start with $S$ on the stack. Repeatedly look at the top: if it is a variable $A$, nondeterministically replace it by the right side of some rule $A \to w$ (guessing the derivation). If it is a terminal $a$, it must match the next input symbol — pop it and read it. Accept when the stack is empty and the input is used up. This is exactly a top-down (LL) parser, minus the lookahead that makes real parsers deterministic.

A three-state construction: $q_\text{start} \xrightarrow{\varepsilon,\varepsilon\to S\bot} q_\text{loop}$; at $q_\text{loop}$ add a self-loop $\varepsilon, A \to w$ for every rule $A \to w$ and $a, a \to \varepsilon$ for every terminal; finally $q_\text{loop} \xrightarrow{\varepsilon,\bot\to\varepsilon} q_\text{acc}$. PDA → CFG (sketch)

First normalize the PDA: a single accept state, the stack is empty when accepting, and every move either pushes one symbol or pops one symbol. Then create a variable $A_{pq}$ for every pair of states, generating exactly the strings that take the PDA from $p$ with an empty stack to $q$ with an empty stack. Consider the first push and the matching last pop of such a computation:

  • if the symbol pushed first is popped only at the very end: $A_{pq} \to a\,A_{rs}\,b$ (where $a$ is read on the push $p \to r$, $b$ on the pop $s \to q$);
  • otherwise the stack becomes empty somewhere in the middle at state $r$: $A_{pq} \to A_{pr}A_{rq}$;
  • and $A_{pp} \to \varepsilon$.

The start variable is $A_{q_0 q_\text{acc}}$. Proving both directions is a careful induction on derivation length / computation length.

Deterministic PDAs

Definition — DPDA

A PDA is deterministic if in every configuration at most one move is possible (including ε-moves). Languages recognized by DPDAs (by final state) are the deterministic context-free languages (DCFLs).

  • DCFLs ⊊ CFLs. For example $\{ww^R\}$ is context-free but not deterministic: a DPDA cannot know where the middle is. By contrast, $\{w\,c\,w^R\}$ (with an explicit centre marker $c$) is a DCFL.
  • DCFLs are closed under complement (unlike CFLs) and are never inherently ambiguous.
  • DCFLs are exactly the languages of LR(k) grammars — the class used by parser generators like yacc and bison. Programming-language designers deliberately keep syntax deterministic so it can be parsed in linear time.
Pitfall — for PDAs, nondeterminism adds power

For finite automata, NFA = DFA. For Turing machines, NTM = DTM (in power). For pushdown automata, NPDA ≠ DPDA. You cannot “subset-construct” a PDA, because different branches have different stacks and the set of possible stacks is unbounded.

Exercises

Design a PDA for $\{a^ib^j : i \ge j\}$. easy

Push ⊥; push an $a$ per $a$; on each $b$ pop an $a$ (move to a “b-phase” state on the first $b$). Accept at the end in the b-phase or a-phase regardless of what remains on the stack (leftover $a$’s are fine). Make the start and the a-phase accepting too, so $\varepsilon$ and $a^i$ are accepted.

Design a PDA for strings over $\{a,b\}$ with equally many $a$’s and $b$’s. medium

Use the stack as a signed counter. After ⊥: on $a$, if the top is $b$ pop it, else push $a$; on $b$, if the top is $a$ pop it, else push $b$. Accept (via $\varepsilon, \bot \to \varepsilon$ to the accept state) when ⊥ is on top at the end. The stack always contains only $a$’s or only $b$’s, recording the surplus.

Trace the palindrome PDA on 0110, listing the configurations of the accepting branch. easy

$(q_1, 0110, \varepsilon) \vdash (q_2, 0110, \bot) \vdash (q_2, 110, 0\bot) \vdash (q_2, 10, 10\bot) \vdash (q_3, 10, 10\bot) \vdash (q_3, 0, 0\bot) \vdash (q_3, \varepsilon, \bot) \vdash (q_4, \varepsilon, \varepsilon)$. The guess happened after reading 01.

Build the CFG→PDA machine for the balanced-parentheses grammar $S \to (S)S \mid \varepsilon$ and run the simulator in your head on (). medium

Loop transitions: $\varepsilon, S \to (S)S$; $\varepsilon, S \to \varepsilon$; $(, ( \to \varepsilon$; $), ) \to \varepsilon$. Run: stack $S\bot$ → expand to $(S)S\bot$ → read (: $S)S\bot$ → $S \to \varepsilon$: $)S\bot$ → read ): $S\bot$ → $S \to \varepsilon$: $\bot$ → pop ⊥, accept.

Explain intuitively why $\{a^nb^nc^n\}$ seems impossible for a PDA. medium

After pushing $n$ symbols for the $a$’s, checking the $b$’s requires popping them — and then the count is gone when the $c$’s arrive. If instead it keeps the count, it cannot verify the $b$’s. One stack can verify one matching, not two. The next chapter turns this intuition into a proof with the CFL pumping lemma.

Takeaways
  • PDA = NFA + stack. Transitions $a, X \to \gamma$: read $a$, pop $X$, push $\gamma$.
  • A stack matches nesting: last opened, first closed.
  • CFG ⇔ PDA. CFG → PDA simulates leftmost derivations with the stack holding the unmatched suffix; PDA → CFG uses variables $A_{pq}$.
  • Final-state and empty-stack acceptance are equivalent for NPDAs.
  • DPDAs are strictly weaker; DCFLs = LR(k) languages, the basis of practical parsers.
