Decidability & the Halting Problem

Some problems have no algorithm — not because we have not found one, but because none can exist. This chapter proves it for the most famous example: deciding whether a program halts. The proof is short, beautiful, and one of the deepest ideas in all of science.

⏱ 70 minPrerequisite: Chapters 2, 11

Decidable problems about automata

First, the good news. Many questions about the machines from earlier chapters are decidable. Phrased as languages of encodings:

LanguageQuestionDecider
$A_\text{DFA} = \{\langle B, w\rangle : B \text{ a DFA accepting } w\}$Does DFA $B$ accept $w$?simulate $B$ on $w$
$A_\text{NFA}$, $A_\text{REX}$same for NFAs, regexesconvert to a DFA, then as above
$E_\text{DFA} = \{\langle A\rangle : L(A) = \emptyset\}$Is the language empty?reachability of an accept state
$EQ_\text{DFA}$Do two DFAs agree?emptiness of the symmetric difference
$A_\text{CFG} = \{\langle G, w\rangle : G \text{ generates } w\}$Does $G$ generate $w$?CYK (or: convert to CNF and try all derivations of length $2|w|-1$)
$E_\text{CFG}$Is $L(G)$ empty?mark generating variables
$EQ_\text{CFG}$Do two CFGs agree?undecidable!

A consequence: every context-free language is decidable — hard-code its grammar $G$ into a decider for $A_\text{CFG}$. So: regular ⊂ context-free ⊂ decidable ⊆ recognizable.

The acceptance problem for Turing machines

$$A_\text{TM} = \{\langle M, w\rangle : M \text{ is a TM and } M \text{ accepts } w\}.$$

The universal machine $U$ recognizes $A_\text{TM}$: simulate $M$ on $w$ and accept if it accepts. But if $M$ loops on $w$, so does $U$. Could a cleverer machine always halt with the right answer — detecting loops?

Intuition — the program that does the opposite

Suppose someone sells you a function halts(program, input) that always returns True or False correctly. Write this:

def paradox(program):
    if halts(program, program):   # would program halt when fed its own source?
        while True: pass          # ...then loop forever
    else:
        return                    # ...otherwise halt immediately

paradox(paradox)                  # ???

Does paradox(paradox) halt? If halts says yes, it loops. If halts says no, it halts. Either way halts was wrong. So no such function can exist. That is the whole proof; the rest is making it precise.

The proof: diagonalization

Theorem (Turing, 1936) — $A_\text{TM}$ is undecidable

No Turing machine decides $A_\text{TM}$.

Suppose $H$ decides $A_\text{TM}$: $H(\langle M, w\rangle)$ accepts if $M$ accepts $w$ and rejects otherwise (always halting). Build a new machine $D$:

$D$ on input $\langle M\rangle$: run $H$ on $\langle M, \langle M\rangle\rangle$. If $H$ accepts, reject; if $H$ rejects, accept.

$D$ always halts, because $H$ does. Now run $D$ on its own description:

$$D(\langle D\rangle) = \begin{cases}\text{accept} & \text{if } D \text{ does not accept } \langle D\rangle\\ \text{reject} & \text{if } D \text{ accepts } \langle D\rangle\end{cases}$$

$D$ accepts $\langle D\rangle$ if and only if it does not. Contradiction — so $H$ cannot exist.

The Halting Problem

$$\textit{HALT}_\text{TM} = \{\langle M, w\rangle : M \text{ halts on } w\}$$

is also undecidable. Intuitively it is the same problem: if we could decide halting, we could decide acceptance by first checking whether $M$ halts on $w$ and, if so, simulating it to see the answer. The next chapter makes this “if we could solve X we could solve Y” reasoning into a general tool called reduction.

Pitfalls — what the theorem does NOT say
  • It does not say we can never tell whether a particular program halts. For many programs we can (and tools do). It says no single algorithm works for all programs.
  • It does not depend on Turing machines specifically: by the Church–Turing thesis, it holds for every programming language.
  • It is not about running time. Giving the decider more time does not help; “run it for a billion steps and see” fails on programs that halt after a billion and one.

Recognizable, co-recognizable, decidable

$A_\text{TM}$ is recognizable (by $U$) but not decidable. What about its complement?

Definition — co-Turing-recognizable

$L$ is co-Turing-recognizable if $\overline{L}$ is Turing-recognizable.

Theorem — decidable = recognizable ∩ co-recognizable

$L$ is decidable if and only if both $L$ and $\overline{L}$ are Turing-recognizable.

(⇒) A decider for $L$ is a recognizer for $L$; swapping its answers recognizes $\overline{L}$. (⇐) Let $M_1$ recognize $L$ and $M_2$ recognize $\overline{L}$. On input $w$, run both in parallel (alternating steps). Every $w$ is in exactly one of $L$, $\overline{L}$, so exactly one of them eventually accepts. If $M_1$ accepts, accept; if $M_2$ accepts, reject. This always halts.

Corollary — $\overline{A_\text{TM}}$ is not Turing-recognizable

If it were, $A_\text{TM}$ would be both recognizable and co-recognizable, hence decidable — contradiction.

Intuition — “yes” can be certified, “no” cannot

If $M$ accepts $w$, there is a finite proof: the accepting computation. You can find it by simulating. If $M$ does not accept $w$ because it loops, there may be no finite evidence at all. Recognizable problems are those whose “yes” answers have finite certificates you can search for.

Exercises

Show that $\textit{INFINITE}_\text{DFA} = \{\langle A\rangle : L(A) \text{ is infinite}\}$ is decidable. easy

Remove states not reachable from the start and states that cannot reach an accept state; $L(A)$ is infinite iff a cycle remains. Alternatively: with $n$ states, $L(A)$ is infinite iff it contains a string of length between $n$ and $2n-1$ (pumping), which can be tested exhaustively.

Is $\{\langle M\rangle : M \text{ is a TM that halts on input } \varepsilon \text{ within 1000 steps}\}$ decidable? easy

Yes: simulate $M$ on $\varepsilon$ for at most 1000 steps. Bounding the time removes the difficulty.

Where exactly does the proof break if we try to show $A_\text{DFA}$ is undecidable the same way? medium

The diagonal machine $D$ would have to be a DFA (to be in the list of DFAs and be fed its own description). But $D$ must run the decider $H$ for $A_\text{DFA}$ on $\langle M, \langle M\rangle\rangle$ — simulating an arbitrary DFA described in its input — which no DFA can do. The contradiction disappears because $D$ is not in the class. The diagonal argument needs the class to be powerful enough to simulate its own members.

Show that if $L$ is recognizable and $\overline{L}$ is recognizable, and $L$ is infinite, it still need not be regular. easy

Take $L = \{0^n1^n\}$: decidable (so both $L$ and $\overline{L}$ are recognizable) and infinite, but not regular. Decidability is a much coarser notion than regularity.

Prove that the class of Turing-recognizable languages is closed under intersection, but give an argument why it is not closed under complement. medium

Intersection: run $M_1$; if it accepts, run $M_2$; accept if both accept (if either loops, the input is not in the intersection anyway, so looping is fine). Not closed under complement: $A_\text{TM}$ is recognizable, $\overline{A_\text{TM}}$ is not.

Takeaways
  • Questions about DFAs (and most about CFGs) are decidable; every CFL is decidable.
  • $A_\text{TM}$ is recognizable but undecidable — proof by diagonalization (“the machine that does the opposite of what it is predicted to do”).
  • $\textit{HALT}_\text{TM}$ is undecidable too.
  • Decidable ⇔ recognizable and co-recognizable. Hence $\overline{A_\text{TM}}$ is not even recognizable.
