Chapter 5 · Regular Languages

Regular Expressions

Automata describe languages as machines; regular expressions describe them as formulas. Kleene’s theorem says the two describe exactly the same languages — and the proof gives the algorithms behind every regex engine.

⏱ 60 minPrerequisite: Chapter 4

The intuition

Intuition — patterns from three operations

Every regular pattern can be built from single symbols using only three ideas:

  • or (union): “a cat or a dog”;
  • then (concatenation): “a digit, then a letter”;
  • repeat (star): “any number of digits, possibly none”.

That is the complete toolkit. There is no “count”, no “remember”, no “match the same thing again”. Which is precisely why regular expressions correspond to finite memory.

Definition

Definition — regular expressions over Σ (inductive)

Base cases:

  • $a$ for each $a \in \Sigma$ is a regular expression, with $L(a) = \{a\}$;
  • $\varepsilon$ is a regular expression, with $L(\varepsilon) = \{\varepsilon\}$;
  • $\emptyset$ is a regular expression, with $L(\emptyset) = \emptyset$.

Inductive cases, if $R_1, R_2$ are regular expressions:

  • $(R_1 \cup R_2)$ with $L = L(R_1) \cup L(R_2)$ — also written $R_1 + R_2$ or $R_1 \mid R_2$;
  • $(R_1 R_2)$ with $L = L(R_1)L(R_2)$;
  • $(R_1^*)$ with $L = L(R_1)^*$.

Precedence: star binds tightest, then concatenation, then union. So $ab^* \cup c$ means $\big(a(b^*)\big) \cup c$. Shorthands: $R^+ = RR^*$ (one or more), $R? = R \cup \varepsilon$ (optional), and $\Sigma$ for “any symbol”.

Algebraic laws

Regular expressions form an algebra. Two expressions are equivalent if they denote the same language. Useful identities:

LawIdentity
Union is associative, commutative, idempotent$R \cup S = S \cup R$, $R \cup R = R$
Identities$R \cup \emptyset = R$, $R\varepsilon = \varepsilon R = R$
Annihilator$R\emptyset = \emptyset R = \emptyset$
Distributivity$R(S \cup T) = RS \cup RT$, $(S \cup T)R = SR \cup TR$
Star laws$(R^*)^* = R^*$, $\emptyset^* = \varepsilon^* = \varepsilon$, $R^* = \varepsilon \cup RR^*$
Sliding / shifting$(RS)^*R = R(SR)^*$
Denesting$(R \cup S)^* = (R^*S)^*R^* = (R^* S^*)^*$
Pitfall — concatenation does not commute, and star does not distribute

$RS \ne SR$ in general ($ab \ne ba$). And $(R \cup S)^* \ne R^* \cup S^*$: the left side contains $ab$, the right side does not. Also $(RS)^* \ne R^*S^*$: the right side contains $aab$, the left does not when $R=a,S=b$.

Kleene’s theorem

Theorem (Kleene, 1956)

A language is regular (recognized by some DFA / NFA) if and only if it is described by some regular expression.

We prove both directions constructively — each direction is an algorithm.

Direction 1: regex → NFA (Thompson’s construction)

Build an NFA by structural induction on the expression. Each piece has one start state and one accept state, and pieces are glued with ε-arrows:

Thompson’s construction gives an NFA linear in the size of the regex; simulating it with the set-of-states algorithm gives matching in $O(|R|\cdot|w|)$ time — guaranteed, with no exponential backtracking.

Direction 2: automaton → regex (state elimination)

Allow arrows to be labelled by regular expressions instead of single symbols — a generalized NFA (GNFA). Then remove states one at a time, patching the arrows so the language is preserved, until only a start and an accept state remain. The label on the last arrow is the answer.

  1. Add a new start state with an ε-arrow to the old start, and a new accept state with ε-arrows from all old accept states. Merge parallel arrows with $\cup$.
  2. Pick a state $q$ to remove. For every pair of states $p \to q \to r$, replace by a direct arrow $p \to r$ labelled $$R_{pq}\,(R_{qq})^*\,R_{qr} \;\cup\; R_{pr}$$ where $R_{qq}$ is the self-loop at $q$ (use $\varepsilon$ if none) and $R_{pr}$ is any existing direct arrow.
  3. Repeat until only start and accept remain.
Intuition — the formula is a path summary

Any path that used to go through $q$ looks like: enter $q$ ($R_{pq}$), loop at $q$ any number of times ($R_{qq}^*$), leave ($R_{qr}$). Or it never touched $q$ ($R_{pr}$). That is all the formula says.

Worked example — even number of 0s

DFA: $E \xrightarrow{0} O$, $O \xrightarrow{0} E$, both loop on 1; $E$ is start and accept. Add new start $S \xrightarrow{\varepsilon} E$ and new accept $E \xrightarrow{\varepsilon} A$.

Eliminate $O$: the only path through it is $E \xrightarrow{0} O \xrightarrow{0} E$ with loop $1$ at $O$, giving a new self-loop at $E$: $01^*0$. Combined with the existing loop $1$, $E$ now loops on $1 \cup 01^*0$.

Eliminate $E$: $S \xrightarrow{\varepsilon} E \xrightarrow{\varepsilon} A$ with loop $1 \cup 01^*0$ gives

$$S \xrightarrow{\ (1 \cup 01^*0)^*\ } A.$$

So the language is $(1 \cup 01^*0)^*$ — read it as “a sequence of blocks, each either a single 1 or a pair of 0s with 1s in between.”

Different elimination orders give different (but equivalent) expressions, and the result can be exponentially long in the worst case — regexes are sometimes far less succinct than automata.

Arden’s lemma (the algebraic route)

Alternatively, write one equation per state: $X_q$ = the set of strings that lead from $q$ to acceptance. For example $X_E = 1X_E \cup 0X_O \cup \varepsilon$ and $X_O = 1X_O \cup 0X_E$. Solve with:

Arden’s lemma

If $\varepsilon \notin L(A)$, the equation $X = AX \cup B$ has the unique solution $X = A^*B$.

From the second equation $X_O = 1^*0X_E$; substitute: $X_E = (1 \cup 01^*0)X_E \cup \varepsilon$, so $X_E = (1 \cup 01^*0)^*$ — the same answer.

Theory regexes vs. programmers’ regexes

The regex in your programming language is a superset of the theory:

  • Pure conveniences (still regular): character classes [a-z], \d, +, ?, {2,5}, anchors.
  • Non-regular extensions: backreferences: (a+)b\1 matches $\{a^n b a^n : n \ge 1\}$, which is not regular, and (.*)\1 matches $\{ww\}$, which is not even context-free. Matching with backreferences is NP-hard.
  • Engines: backtracking engines (Perl, Python re, Java, JavaScript) can take exponential time on patterns like (a+)+$ against aaaa…ab — the infamous ReDoS attacks. Automaton-based engines (RE2, Go, Rust regex) use the NFA/DFA constructions from these chapters and run in linear time, at the price of not supporting backreferences.

Exercises

Write a regex over $\{0,1\}$ for strings that contain both 00 and 11. medium

$\Sigma^*00\Sigma^*11\Sigma^* \;\cup\; \Sigma^*11\Sigma^*00\Sigma^*$. Either occurrence can come first. (Note the occurrences cannot overlap since 00 and 11 share no symbol.)

Describe $(0 \cup 1)^*0(0 \cup 1)(0 \cup 1)$ in words. easy

Strings of length at least 3 whose third symbol from the end is 0.

Write a regex for binary strings with no two consecutive 1s. Test it in the regex lab. medium

$(0 \cup 10)^*(\varepsilon \cup 1)$ — in the lab: (0|10)*(ε|1). Every 1 except possibly the last must be followed by a 0.

Prove or disprove: $(R^*S^*)^* = (R \cup S)^*$. medium

True. ⊆: every string in $R^*S^*$ is a concatenation of pieces from $R$ and $S$, so belongs to $(R\cup S)^*$, and the latter is closed under concatenation. ⊇: any string in $(R \cup S)^*$ is a sequence of pieces each in $R$ or $S$; each piece alone is in $R^*S^*$ (with the other factor $\varepsilon$), so the sequence is in $(R^*S^*)^*$.

Convert the DFA for “ends in 01” (states $q_0, q_1, q_2$ from Chapter 3) to a regex using state elimination. hard

The expected answer is equivalent to $(0\cup1)^*01$. One route via Arden: let $X_i$ be the strings leading from $q_i$ to acceptance. $X_0 = 1X_0 \cup 0X_1$, $X_1 = 0X_1 \cup 1X_2$, $X_2 = 0X_1 \cup 1X_0 \cup \varepsilon$. Any correct elimination yields a regex denoting “strings ending in 01”; for exams, it is fine to then simplify to $\Sigma^*01$ and justify by the language description.

How many states does Thompson’s construction produce for $a^*b$? Draw it. easy

$a$: 2 states; $a^*$: adds 2 → 4; $b$: 2 states; concatenation adds no states → 6 states in total. (Some presentations merge states and get fewer — the exact count depends on the variant, but it is always linear in the regex size.)

Takeaways
  • Regexes: $\emptyset$, $\varepsilon$, symbols, closed under $\cup$, concatenation and $^*$. Precedence: star > concat > union.
  • Kleene: regex ≡ NFA ≡ DFA. Regex → NFA by Thompson (linear size); NFA → regex by state elimination or Arden’s lemma.
  • Elimination rule: $R_{pq}R_{qq}^*R_{qr} \cup R_{pr}$.
  • Practical regexes with backreferences are not regular; backtracking engines can be exponential, automaton engines are linear.
