Turing Machines

In 1936 Alan Turing asked what a human “computer” — a person following rules with pencil and paper — can do in principle. His answer, a machine with a finite rulebook and an unbounded tape, turned out to capture every algorithm anyone has ever devised.

⏱ 80 minPrerequisite: Chapters 3, 92 runnable Turing machines

The intuition

Intuition — a clerk with an infinite strip of paper

Imagine a clerk who can see one square of an endless paper tape at a time. Each square holds one symbol. The clerk has a finite rulebook and is always in one of finitely many “moods” (states). A rule says: “in mood q, seeing symbol a: write b, step left or right, switch to mood r.” That is all.

Compared with a PDA, two things changed: the memory is random-access in principle (walk anywhere, not just the top of a stack), and it is rewritable. Those two changes give it the full power of computation.

Definition

Definition — Turing machine

A TM is a 7-tuple $M = (Q, \Sigma, \Gamma, \delta, q_0, q_\text{acc}, q_\text{rej})$ where

  • $Q$ is a finite set of states;
  • $\Sigma$ is the input alphabet, not containing the blank symbol ␣;
  • $\Gamma \supseteq \Sigma \cup \{␣\}$ is the tape alphabet;
  • $\delta : Q \times \Gamma \to Q \times \Gamma \times \{L, R\}$ is the transition function;
  • $q_0$ is the start state; $q_\text{acc}$ and $q_\text{rej}$ are the accept and reject states ($q_\text{acc} \ne q_\text{rej}$).

The input is written on the leftmost cells of an otherwise blank, one-way-infinite tape; the head starts on the first cell. The machine runs until it enters $q_\text{acc}$ or $q_\text{rej}$ — or forever.

A configuration is written $u\,q\,v$: the tape contains $uv$ (followed by blanks), the machine is in state $q$, and the head is on the first symbol of $v$. For example $1x\,q_2\,0y$ means the head is reading the $0$. One step is written $C \vdash C'$.

Three possible outcomes

On input $w$ a TM can accept, reject, or loop (run forever). This third outcome is new and changes everything:

Definition — recognizable vs. decidable
  • $M$ recognizes $L$ if it accepts exactly the strings in $L$ (it may reject or loop on the others). $L$ is Turing-recognizable (recursively enumerable, semi-decidable).
  • $M$ decides $L$ if it recognizes $L$ and halts on every input. $L$ is decidable (recursive). $M$ is called a decider.

A recognizer is like a search that will announce success if there is something to find, but might search forever if there is not. The difference between the two notions is the subject of the next chapter.

Example 1 — deciding $0^n1^n$

Strategy: repeatedly cross off the leftmost 0 (write x) and the leftmost 1 (write y), zig-zagging across the tape. When no 0s remain, check that no 1s remain either.

This machine takes about $n^2$ steps on $0^n1^n$ — each of the $n$ rounds walks across the input. A two-tape machine could do it in linear time (copy the 0s to tape 2, then match). We will care about such differences in Chapter 15.

Notice that $\{0^n1^n2^n\}$ — not context-free — is just as easy for a TM: cross off one of each per round. TMs are strictly more powerful than PDAs.

Example 2 — computing a function: binary increment

TMs can also compute: the output is whatever is on the tape when the machine halts.

Three levels of description

Nobody writes full transition tables for interesting machines. Following Sipser, we describe TMs at three levels:

  1. Formal: the 7-tuple and every transition (as above).
  2. Implementation: in English, how the head moves and what it writes (“scan right to the first 1, cross it off, return to the left end”).
  3. High-level: an algorithm in pseudocode, ignoring the tape entirely (“sort the list; check whether…”).

The rest of this course works mostly at the high level. That is justified by the robustness results and the Church–Turing thesis below: anything you can write as an algorithm, some TM can do.

Variants — and why they don’t matter

Many modifications seem more powerful. None of them is. Each can be simulated by a standard TM:

Intuition — two stacks make a tape

One stack is weak (context-free). Two stacks are as powerful as a Turing machine: everything left of the head lives on stack A, everything right of it on stack B. Moving the head right = pop from B, push onto A. This is a great way to remember where the line between “PDA” and “computer” really is.

Enumerators

An enumerator is a TM with a printer that, starting on a blank tape, prints a (possibly infinite) list of strings. A language is Turing-recognizable iff some enumerator prints exactly its strings — the origin of the name “recursively enumerable”. (To turn a recognizer into an enumerator, run it on $s_1, \dots, s_i$ for $i$ steps each, for $i = 1, 2, 3, \dots$ — dovetailing, so that no looping input blocks the others.)

The Church–Turing thesis

The Church–Turing thesis

Every function that is effectively computable — computable by any mechanical, step-by-step procedure — is computable by a Turing machine.

This is a thesis, not a theorem: “effectively computable” is an informal notion, so it cannot be proved. The evidence is overwhelming: every model ever proposed — Church’s λ-calculus, Gödel–Kleene μ-recursive functions, Post systems, register machines, cellular automata (even the one-dimensional Rule 110), every programming language — computes exactly the same class of functions. Systems equivalent to TMs are called Turing-complete.

The thesis is what lets us say “there is no algorithm for the Halting Problem” — not just “no Turing machine”.

Machines as data: encodings and the universal TM

A Turing machine is a finite object, so it can be written down as a string. We write $\langle M \rangle$ for an encoding of $M$, $\langle M, w\rangle$ for an encoding of the pair, $\langle G \rangle$ for a graph, and so on. The details do not matter as long as a TM can decode them.

Theorem (Turing, 1936) — a universal Turing machine exists

There is a TM $U$ that, given $\langle M, w\rangle$, simulates $M$ on $w$: it accepts if $M$ accepts, rejects if $M$ rejects, and loops if $M$ loops.

$U$ keeps $\langle M\rangle$ on one tape as a rulebook, $M$’s tape contents on another, and $M$’s current state on a third, and repeatedly looks up and applies the right rule. This is the stored-program computer — the idea that a single fixed machine can run any program given as data — a decade before anyone built one. Every interpreter, virtual machine and emulator is a universal machine.

Exercises

Give the sequence of configurations of the $0^n1^n$ machine on input 01. easy

$q_0\,01 \vdash x\,q_1\,1 \vdash q_2\,xy \vdash x\,q_0\,y \vdash xy\,q_3\,␣ \vdash xy␣\,q_\text{acc}$. Accept.

Describe (implementation level) a TM that decides $\{w\#w : w \in \{0,1\}^*\}$. medium

Zig-zag: remember (in the state) the first unmarked symbol left of # and cross it off; move right past # to the first unmarked symbol and check it matches, crossing it off; return to the left. If no # exists, reject. When all symbols left of # are crossed off, check that all symbols right of # are too. Accept iff all checks pass. (Recall $\{w\#w\}$ is not context-free!)

Why can a TM with a tape that is read-only (no writing allowed) recognize only regular languages? hard

Without writing, the only memory is the finite state and the head position. The head can wander back and forth over the input, but such two-way finite automata are known to recognize exactly the regular languages (Rabin–Scott/Shepherdson): one can summarize, for each prefix, a finite “crossing table” of how the machine behaves when it crosses the boundary — finitely many possibilities, so a one-way DFA can track them.

Show that the class of decidable languages is closed under complement, union, and intersection. easy

Complement: run the decider and swap accept/reject (it always halts). Union/intersection: run both deciders one after the other (both halt) and combine the answers with OR/AND.

Show that Turing-recognizable languages are closed under union. Why can’t you just run $M_1$ and then $M_2$? medium

If $M_1$ loops on $w$ and $M_2$ accepts it, running $M_1$ first never gets to $M_2$. Instead run them in parallel, alternating one step of each (or using two tapes); accept as soon as either accepts. This dovetailing trick appears again and again.

Modify the increment machine so that it decrements instead (assume the input is positive). medium

Same structure, with the roles of 0 and 1 swapped in the borrow phase: walk right to the end; then in the borrow state turn trailing 0s into 1s moving left ($0 \to 1, L$), and when a 1 is found turn it into 0 and halt ($1 \to 0$, accept).

Takeaways
  • TM: finite control + unbounded read/write tape; $\delta(q, a) = (r, b, D)$.
  • Three outcomes: accept, reject, loop. Recognizable = accepts exactly $L$; decidable = also always halts.
  • Multi-tape, nondeterministic, two-stack, RAM: all equally powerful (with polynomial or exponential slowdowns).
  • Church–Turing thesis: TMs capture every algorithm.
  • Machines are strings $\langle M\rangle$; a universal TM can run any of them.
