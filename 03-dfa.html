Chapter 3 · Regular Languages

Deterministic Finite Automata

The simplest useful model of computation: a machine that reads its input once, left to right, and can remember only one of finitely many things. Learning to design these is learning to ask the most important question in computing — what do I actually need to remember?

⏱ 60 minPrerequisite: Chapter 24 interactive machines

The intuition

Intuition — a state is a summary of the past

Picture someone reading a very long string, one symbol at a time, through a tiny window. They cannot go back, and they have a small whiteboard that can show only one of a fixed set of messages. After each symbol they may erase the whiteboard and write a different message. At the end, they must say yes or no by looking only at the whiteboard.

The messages are the states. The rule “if the board says X and I read symbol a, write Y” is the transition function. The design challenge is choosing messages that summarize everything about the past that could matter for the future — and nothing more.

“Deterministic” means there is never a choice: from each state, each symbol leads to exactly one next state. The machine’s behaviour on any input is completely determined.

Formal definition

Definition — DFA

A deterministic finite automaton is a 5-tuple $M = (Q, \Sigma, \delta, q_0, F)$ where

  • $Q$ is a finite set of states;
  • $\Sigma$ is a finite input alphabet;
  • $\delta : Q \times \Sigma \to Q$ is the transition function (total: defined for every state and symbol);
  • $q_0 \in Q$ is the start state;
  • $F \subseteq Q$ is the set of accept (final) states.

To talk about whole strings we extend $\delta$ to the extended transition function $\hat\delta : Q \times \Sigma^* \to Q$, defined by induction on the string:

$$\hat\delta(q, \varepsilon) = q \qquad\qquad \hat\delta(q, wa) = \delta\big(\hat\delta(q, w),\, a\big)$$

In words: on the empty string you stay put; to process $wa$, process $w$ first, then take one more step on $a$.

Definition — acceptance and the language of a DFA

$M$ accepts $w$ if $\hat\delta(q_0, w) \in F$; otherwise it rejects. The language of $M$ is $L(M) = \{ w \in \Sigma^* : \hat\delta(q_0, w) \in F \}$. A language is regular if some DFA recognizes it.

A DFA can be given in three equivalent ways: the tuple, a state diagram (circles and arrows), or a transition table. Get fluent at switching between them.

Example 1 — an even number of 0s

Language: $L_1 = \{ w \in \{0,1\}^* : w \text{ contains an even number of } 0\text{s}\}$. What must we remember? Only the parity of the zeros seen so far. Two states suffice.

Example 2 — binary numbers divisible by 3

Read a binary number most significant bit first. If the prefix so far has value $n$, appending bit $b$ gives value $2n + b$. We cannot store $n$ (it grows without bound), but we only care about $n \bmod 3$, and

$$(2n + b) \bmod 3 = \big(2 \cdot (n \bmod 3) + b\big) \bmod 3.$$

Intuition — remember the answer to the future’s question

The machine does not need to know the number; it needs to know which remainder the future will be built on. This generalizes: a DFA for “divisible by $k$” in base $b$ needs exactly $k$ states, with $\delta(r, d) = (b\cdot r + d) \bmod k$.

Example 3 — strings that end in 01

Here we must remember how much of the target pattern 01 we have just seen at the end of the input:

  • $q_0$: the input does not end in 0 or 01 (nothing useful).
  • $q_1$: the input ends in 0 (half of the pattern).
  • $q_2$: the input ends in 01 (accept).
Pitfall — forgetting overlaps

A frequent mistake in pattern-matching DFAs is to “reset to the start” on a mismatch. In $q_1$ (we just saw 0), reading another 0 must stay in $q_1$, because the new 0 could still be the start of 01. The correct target after a mismatch is the state for the longest suffix of what you have read that is still a prefix of the pattern. (This is exactly the idea behind the Knuth–Morris–Pratt string-matching algorithm.)

Dead states and completeness

Consider $L = \{ w : w \text{ starts with } 1 \}$. Once the first symbol is a 0, the answer is “no” forever. We model this with a dead (trap) state: a non-accepting state that loops to itself on every symbol.

A design method that always works

  1. Read the language as a question about the future. “Given what I have read, what could still happen?”
  2. Choose the information to remember. Parities, remainders, “how much of the pattern have I matched”, “have I already seen X”, “the last $k$ symbols”, small counters capped at some value.
  3. Make one state per possible value of that information.
  4. Fill in transitions by asking: if I know this and read symbol $a$, what do I know now?
  5. Mark accept states: which values mean “yes, if the input ended now”?
  6. Check $\varepsilon$, a few short strings, and boundary cases. Then state the invariant (“in state $q$ iff …”) and, if needed, prove it by induction on $|w|$.

The product construction

Suppose we want strings with an even number of 0s and an odd number of 1s. We already know how to track each property with two states. Run both machines in parallel: a state is a pair (state of machine 1, state of machine 2).

Construction — product automaton

Given $M_1 = (Q_1, \Sigma, \delta_1, s_1, F_1)$ and $M_2 = (Q_2, \Sigma, \delta_2, s_2, F_2)$, define $M = (Q_1 \times Q_2, \Sigma, \delta, (s_1, s_2), F)$ with

$$\delta\big((p, q), a\big) = \big(\delta_1(p, a), \delta_2(q, a)\big).$$

With $F = F_1 \times F_2$, $L(M) = L(M_1) \cap L(M_2)$. With $F = \{(p,q) : p \in F_1 \text{ or } q \in F_2\}$, $L(M) = L(M_1) \cup L(M_2)$.

The product has $|Q_1| \cdot |Q_2|$ states. This is our first closure property: regular languages are closed under intersection and union. Chapter 6 collects many more.

Complement

For a DFA, complementing the language is trivial: swap accepting and non-accepting states, $F \mapsto Q \setminus F$. This works only because the DFA is complete and deterministic — every string ends in exactly one state. (It fails for NFAs; see the next chapter.) Do not forget to add the dead state before swapping, otherwise strings that “fell off” the diagram will still be rejected.

Proving a DFA correct

For the divisible-by-3 machine, the invariant is:

$$\hat\delta(r_0, w) = r_k \iff \operatorname{val}(w) \equiv k \pmod 3.$$

By induction on $|w|$. Base: $\operatorname{val}(\varepsilon) = 0$ and $\hat\delta(r_0, \varepsilon) = r_0$. Step: suppose it holds for $w$, with $\operatorname{val}(w) \equiv k$. Then $\operatorname{val}(wb) = 2\operatorname{val}(w) + b \equiv 2k + b$, and by construction $\delta(r_k, b) = r_{(2k+b) \bmod 3}$. So the invariant holds for $wb$. Since $F = \{r_0\}$, $M$ accepts exactly the multiples of 3.

Exercises

Design a DFA over $\{a,b\}$ for strings that contain the substring aba. easy

States record the longest suffix that is a prefix of aba: $q_0$ (none), $q_a$, $q_{ab}$, and $q_{aba}$ (found — accepting and absorbing).

Design a DFA over $\{0,1\}$ for strings whose length is divisible by 3. easy

Three states $c_0, c_1, c_2$ counting length mod 3; every symbol (0 or 1) moves $c_i \to c_{(i+1) \bmod 3}$. Accept $c_0$, which is also the start state (so $\varepsilon$ is accepted, length 0).

Design a DFA for strings over $\{0,1\}$ in which every 0 is immediately followed by a 1. medium

Remember whether we owe a 1. State $A$ (nothing owed, accepting, start): 1→$A$, 0→$B$. State $B$ (owe a 1, non-accepting): 1→$A$, 0→Dead. The dead state loops on both symbols. Equivalently the language is $(1 \cup 01)^*$.

How many states does the product construction need for “length divisible by 3 AND ends in 01”? Can you do better? medium

The product has $3 \times 3 = 9$ states. All 9 are reachable and pairwise distinguishable here (the length counter and the suffix tracker are independent), so 9 is in fact minimal. In general the product can sometimes be minimized — Chapter 7 shows how to check.

Give the formal 5-tuple for the “even number of 0s” DFA. easy

$Q = \{E, O\}$, $\Sigma = \{0,1\}$, $q_0 = E$, $F = \{E\}$, and $\delta(E,0)=O$, $\delta(O,0)=E$, $\delta(E,1)=E$, $\delta(O,1)=O$.

Explain why every finite language is regular. medium

Build a trie: one state per prefix of a word in the language, plus a dead state. The start state is $\varepsilon$; from prefix $p$ on symbol $a$ go to $pa$ if it is a prefix of some word, else to dead. Accept the states that are whole words. Finitely many words have finitely many prefixes, so the DFA is finite.

A DFA has $n$ states. Prove that if it accepts any string at all, it accepts one of length less than $n$. hard

Take a shortest accepted string $w$. If $|w| \ge n$, the run on $w$ visits $|w|+1 > n$ states, so some state repeats (pigeonhole). Cut out the loop between the two visits: the shorter string still ends in the same accepting state — contradicting minimality. Hence $|w| \lt n$. This gives an algorithm for “is $L(M)$ empty?”: test all strings shorter than $n$ (or, better, do graph reachability).

Takeaways
  • A DFA is $(Q,\Sigma,\delta,q_0,F)$ with a total, deterministic $\delta$; it accepts $w$ iff $\hat\delta(q_0,w) \in F$.
  • Design by asking “what must I remember about the past?” — one state per possible summary.
  • The product construction runs two DFAs in parallel: intersection and union are regular.
  • Swapping accept states complements a (complete) DFA.
  • Correctness = an invariant per state, proved by induction on the input length.
